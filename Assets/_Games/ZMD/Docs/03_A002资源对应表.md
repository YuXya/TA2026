## 6. 原始格式与当前 Unity 导入设置

下面区分“应该按什么数据解释”和“现在 `.meta` 是什么”。只记录，不修复。

| 输入 | 原始解释 | 后续实现时的注意事项 |
| --- | --- | --- |
| Base / Emission | 本包相关图为 SRGB | 颜色采样要正确解码，不能统一当线性数据贴图 |
| 普通衣料 P | BC7_UNORM | 线性数据，R 金属/G F0 缩放/B AO/A 光滑；不使用旧 ToonURP 通道约定 |
| Diff / Spec Ramp | R8G8B8A8_UNORM | 线性数据采样，保留 Alpha；当前若开启 sRGB 会改 RGB 响应 |
| 暗部 LUT | BC7_SRGB | 输入坐标的 Linear→sRGB 和输出纹理的 sRGB 解码是两件事，不可统一关 sRGB |
| Raw Normal | BC5_UNORM | R/G 存 XY，按 Shader 重建 Z；不能把 Raw 的蓝通道当普通 RGB 法线 |
| Converted_RGB Normal | 单独的转换版本 | 按 Normal Map 方式导入并匹配所用解码；不冒充原始 BC5 字节 |
| 其他控制图 | 逐项看 format 和绑定 | 不能凭图像“像灰度”决定全部格式 |

法线原码可能有 RG/AG 兼容的解包方式，Unity Normal Map 导入也会产生平台相关打包；选择 Raw 自行解码还是 Converted_RGB+Unity 解码，应在写对应 Shader 时明确，不能重复解码。核对切线空间、Y 方向及网格切线。

Ramps/LUT 原参考代码显式采 mip 0，常使用 LinearRepeat；底色多为 LinearClamp，头发部分查表用 LinearMirror。Unity 的 wrap/filter、压缩与 mip 设置应配合具体实现。为了学习而改变采样器/边界保护是允许的实现选择，但需标为与原码的差异。

### 7.1 可以进行、但尚未完成版本核实的推断

**以下都是“若该参数语义与 b468 相同”的条件推断，不是已经证明新 entry 472 的执行路径：**

- `p1.y=1` 会跳过 b468 的体积/SH→HSV 路径，使用 `envTint=p2.xyz≈(.8491,.8958,1.1509)`。因此不能教成“本次场景必定先将采样环境做 HSV 去饱和”。
- `p12.w=0`、曝光 x=1，因此 `envGain≈.28772247`；在固定分支中 E 也为该值。阴影模式 1 系数约 `.65+.35E=.75070`，模式 2 为 1.25，可见环境系数约 .28772，反射系数 .5。`p1.x=0` 选择模式 1；这些都还要乘形状和其他因子。
- `p1.w=1` 会使用 `p11.xyz` 的角色自定义主光方向；不能把场景太阳 Transform 当作唯一 L。
- `p12.x=1` 会关掉 b468 主光 Ramp 坐标中的摄像机非线性重映射权重，并保留 `p11.w≈-.1` 的偏移。
- `iridescentMode=0` 不经虹彩混合将 SpecRamp 色带入环境 F0；也不代表漫反射 Ramp 对反射强度的影响消失。
- `p1.y` 在后面的 `lerp(envTint,1,p1.y*aLight)` 中再次出现，所以固定环境色也不意味着它在所有明暗位置都原样相乘。

这组新证据应补充此前“缺少运行时全局参数”的结论：现在已有一部分捕获参数，但仍缺版本/布局一致性和完整管线输入验证。

## 8. 不完整的运行时输入

`15_SceneBuffers_DebugOnly` 内的图是阴影/预通道诊断 PNG，不是角色 UV 贴图，也不是完整精度、全部时序的运行时缓冲。场景深度、屏幕阴影、多层 3D 辐照度体积的绑定虽有记录，这个包没有将它们完整导出成可直接重放的场景。

因此资源层面“够开始学”与“已经可完全重现原帧”是两件事。若要最终比较，仍需模型/相机/法线切线、实际 Shader 变体、光照方向与颜色、阴影输入、反射、曝光及后处理共同对齐。原资源只有 mip 0 的二维贴图，重新生成的 mip 也不等于原始 mip 链。
