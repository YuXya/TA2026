# 画面对照与验证

## 验证条件

Unity 2022.3.62f3、URP 14.0.12、Linear、Direct3D11、RTX 5060。隔离工程复制当前工程高质量 URP 的灯光／阴影配置，使用独立 Renderer；相机关闭 MSAA 和 Unity 内置后处理。角色保持抓帧姿势、FOV=20°、3840×2160，材质使用抓帧时间，曝光乘数为 1。最终输出积累 16 个 Unity TAA 帧。

参考是抓帧 EID 2167 的角色与环境最终调色结果，排除之后的游戏 UI。原始交换链图另保存在证据目录。参考图只做上下方向校正，比较中没有拟合曝光、颜色、位置或对比度。差分为显示 sRGB 逐通道绝对差，放大 8 倍方便观察；指标仍使用未放大的数据。

## 实际结果

| 区域 | 平均绝对误差（0–255） | PSNR（dB） |
|---|---:|---:|
| 全画面 | 1.77 | 33.69 |
| 角色矩形范围 | 2.99 | 29.41 |
| 衣料局部 | 3.49 | 29.40 |
| 身体皮肤局部 | 3.50 | 29.00 |
| 脸部局部 | 4.07 | 29.33 |
| 头发局部 | 9.59 | 20.70 |
| 眼睛局部 | 3.82 | 30.33 |

这些是固定矩形区域，包含边界和遮挡交界，不是只挑选同色内部像素。矩形坐标、P99 和最大误差见 `COMPARISON_METRICS.json`。头发仍是误差最大的部位；不能用全画面中占比很大的背景稀释这个问题。

## 分阶段证据

1. **几何**：主体使用实际 post-VS 位置、法线、切线、UV 与索引。环境位置通过抓帧投影反算。描边另外解码原始顶点 UV2 的 SNORM／Float 平滑法线，保留片元法线与扩张法线的区别。九次描边与抓帧 post-VS 对照，平均屏幕位置误差均小于 0.00012 像素，最大约 0.0204 像素。`GEOMETRY_TESTS.json` 保存每事件数据。
2. **材质输入**：31 个网格／材质、160 项保存的贴图引用审计通过；共用接口中不被当前通道读取的继承属性已在绑定表注明。资源全部位于 FullRestore。反射 Cubemap 具有六面、8 级 mip。两次脸和两层头发、描边顶点遮罩、眼部模板及乘色叠加分别保留。
3. **线性光照**：原始 b497 GPU 函数与当前函数做 144 项对照，覆盖不同 S/G/E、金属度、粗糙度、清漆和完整半角向量，最大绝对误差 1.192093×10⁻⁷。固定环境、Default SH 与合成 3D 体积输入也通过。具体记录在 `BOUNDARY_TESTS.txt`。
4. **抓帧像素**：六个固定衣料／皮肤像素使用抓帧输入时，附加灯之前的完整组合与原始源码 GPU 对照达到约 10⁻⁷；附加灯后侧身样本仍有约 5.25×10⁻⁵ 的差异。对应 RGB、位置和模式记录在 `COMPARISON_METRICS.json`，这不是最终画面零误差声明。
5. **后处理**：直接输入原抓帧纹理，Bloom prefilter 平均误差 1.12×10⁻⁵，第一层 downsample 3.32×10⁻⁷；UberPost 显示线性结果平均误差 0.001234、最大 0.005103。最大误差与 HDR 中间格式和原目标 8-bit 量化有关。`POST_TESTS.json` 保留原始结果；尚未对每个 TAA 历史状态做逐像素数值验收。
6. **交互**：九种显示、相机旋转、主光旋转、抓帧附加灯开关、新增点光、点光／聚光阴影开关，以及静止和转动后的时序画面均产生有限值；主光和附加光响应检查通过。用事件 ID 确认不透明表面后，五个显示项相加复原组合输出，四个样本误差为 0。详见 `SCENE_TESTS.txt`。

## 已知差异与具体来源

- **实时阴影**：原帧的场景 CSM 已淡出为 R=1，但角色 G 仍来自独立阴影图 54042。这里保留原接收偏移、16 组 Poisson Gather 和遮挡深度处理，由 Unity 主光图集提供实时深度与矩阵。Unity 的级联投影、图集分辨率、深度及采样规则不等于原角色专用投影。头发的深层自阴影因此不同。例如线性像素 (2100,780) 在抓帧 G 输入下与原始源码同为约 (0.30879,0.21779,0.47056)，使用 Unity 阴影后约为 (0.46029,0.33045,0.68106)。这是已定位的阴影输入差异。
- **细发丝、描边和透明交界**：原版依赖法线快照、深度相等、模板、两层头发以及前帧历史。已恢复实际模板状态、顶点遮罩和平滑法线；透明描边按原变体使用几何法线。为避免 Unity 矩阵运算舍入导致零偏移处闪点，零深度偏移时保留输入 z 的位模式，非零时执行原公式。极细边缘的覆盖和时序混合仍未逐像素对齐，局部差分图明确展示这些残余，未认定该部位达到零差异。
- **时序历史**：单个 rdc 中包含原引擎前帧历史，当前 Unity 场景生成自己的 8 样本抖动与历史。没有拿抓帧历史成图填充运行时；两者前帧轨迹和可见性变化无法由单帧完全重建。TAA、景深的收敛与运动边缘残差保留为限制。
- **精度与颜色**：主体计算使用浮点，原管线多个目标为 R11G11B10／R10G10B10A2，最终是 8-bit 输出。法线编码和重采样可产生一个 10-bit 量化单位差异；HDR 累积、Bloom 与调色量化也产生小误差。没有用调色补偿去掩盖这些差异。
- **观察范围**：抓帧环境只含本帧相关几何及 Cubemap，不是完整关卡。转动相机可以观察角色，不意味着镜头外世界、其他姿势或其他时间已获得原版验证。当前可见地面的 SH 遮挡输入为零；没有扩展完整关卡的遮挡生成系统。

## 范围外与未验证

未制作动画系统；未实现本帧关闭的雨雪、近景深；没有验证所有未启用的全局轮廓光／环境模式组合。体积环境采样函数和资源已保留，但本角色抓帧使用固定环境分支。旋转或改光后的稳定性验证，不等于这些新画面已经有原游戏参考。

当前交付包含本帧角色主动使用的表面着色、描边／透明层、实时灯光桥接和后处理。**最终效果仍有上述残余，尤其头发自阴影和细边缘；不称为逐像素完成。**
